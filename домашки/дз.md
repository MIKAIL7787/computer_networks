Транспортный уровень обеспечивает связь между прикладными процессами на разных хостах, используя порты для адресации (от 1 до 65535).

Протокол UDP (User Datagram Protocol) - это дейтаграммный протокол без установления соединения, не гарантирующий доставку, порядок или защиту от потерь.

UDP отличается высокой скоростью и низкими накладными расходами, поэтому используется в DNS, DHCP, TFTP, SNMP и потоковом видео.

Протокол TCP (Transmission Control Protocol) обеспечивает надежную передачу потока байт с установлением соединения, подтверждениями и повторной отправкой потерянных сегментов.

Для надежности TCP использует порядковые номера, кумулятивные подтверждения (ACK) и метод скользящего окна для управления потоком.

Установка TCP-соединения происходит через трехкратное рукопожатие (SYN, SYN+ACK, ACK), а завершение - через обмен сегментами с флагом FIN.

TCP управляет перегрузками сети с помощью алгоритмов медленного старта, предупреждения перегрузок, быстрого повтора и быстрого восстановления.

Размер окна в TCP динамически меняется: окно перегрузки (CWND) устанавливает отправитель, а окно получателя (RWND) объявляет принимающая сторона.

Заголовок UDP составляет 8 байт, а заголовок TCP - минимум 20 байт (без опций) и содержит поля для портов, номеров очереди, подтверждений, флагов и окон.

Выбор между TCP и UDP зависит от требований приложения: TCP - для надежности (HTTP, FTP, SMTP), UDP - для скорости и минимальных задержек (DNS, VoIP, видеопоток).

Сокет - это совокупность IP-адреса и номера порта, однозначно идентифицирующая прикладной процесс (конечную точку) в сети.
