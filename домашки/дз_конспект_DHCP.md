### 1. Назначение и проблема ручной настройки
- Каждому сетевому интерфейсу нужен IP-адрес и другие параметры (маска, шлюз, DNS, домен).
- Ручная настройка требует ведения учёта занятых/свободных адресов, что утомительно даже в малых сетях.
- **DHCP (Dynamic Host Configuration Protocol)** автоматизирует конфигурирование и централизованно управляет распределением адресов, исключая дублирование.

### 2. Предшественники DHCP
- **RARP** (Reverse ARP): клиент рассылал широковещательный запрос, сервер по MAC-адресу возвращал IP.
  - Минусы: сервер в каждом сегменте, ручная регистрация MAC, нет передачи доп. параметров.
- **BOOTP** (Bootstrap Protocol): для бездисковых станций, передавал IP, адрес TFTP-сервера, имя загрузочного файла.
  - Поддерживал **relay** — один сервер на несколько сетей.
  - Минусы: ручная настройка таблиц, ограничение на объём доп. информации.
- **DHCP** — совместимое расширение BOOTP (DHCP-сервер поддерживает старых клиентов, но не наоборот).

### 3. Режимы работы DHCP
1. **Ручное назначение статических адресов** — администратор жёстко закрепляет IP за MAC/идентификатором клиента.
2. **Автоматическое назначение статических адресов** — сервер сам выбирает IP из пула, но закрепляет его за клиентом навсегда (при повторных запросах возвращает тот же адрес).
3. **Динамическое распределение адресов** — IP выдаётся на **срок аренды**; по истечении или при уходе из подсети адрес освобождается и может быть выдан другому.
   - Позволяет обслуживать больше узлов, чем есть IP-адресов.
   - Пример: 500 мобильных сотрудников, из которых в офисе обычно не более 50 → достаточно пула из 64 адресов.

### 4. Алгоритм динамического назначения (упрощённо)
1. Клиент рассылает широковещательный **DHCP-поиск**.
2. Серверы (или **связной DHCP-агент** в другой сети) получают запрос.
3. Серверы отправляют **DHCP-предложения** (IP + параметры).
4. Клиент выбирает первое предложение и рассылает **DHCP-запрос** с указанием выбранного сервера.
5. Выбранный сервер посылает **DHCP-квитанцию**; остальные аннулируют предложения.
6. Клиент переходит в рабочее состояние.

- **Связной агент (relay)** — посредник, пересылающий запросы между сетями; позволяет одному серверу обслуживать несколько сетей.
- **Обновление аренды**: клиент пытается продлить аренду задолго до истечения срока; при неудаче обращается к другому серверу, иначе переходит в автономный режим.
- Можно досрочно отказаться от параметров.

### 5. Проблемы динамических адресов
- **DNS**: сложно поддерживать соответствие имён и меняющихся IP → для серверов обычно статические адреса; развивается **динамический DNS** (согласование баз DHCP и DNS).
- **Удалённое управление и мониторинг**: динамический IP затрудняет доступ и сбор статистики.
- **Безопасность**: фильтрация пакетов по IP усложняется.
- Поэтому статические адреса назначают маршрутизаторам, серверам, принтерам и другим устройствам, чьё местоположение стабильно.

### 6. Ключевые параметры настройки DHCP-сервера
- **Пул адресов** (диапазон).
- **Срок аренды** (зависит от режима работы пользователей: от длительности лабораторной до недель в корпоративной сети).
